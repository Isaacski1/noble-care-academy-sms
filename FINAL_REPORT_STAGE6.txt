## 4. Pagination Added
- Collection: studentFeeLedgers and studentFeePayments (via Firestore queries in db.getStudentLedgers and db.getPayments).
- Page size: 50
- Ordering: relies on the default order from the Firestore queries (as defined in the service methods; we did not change the ordering).
- Cursor strategy: client-side pagination using array slicing (since we already have the full data in state from the Firestore queries). For true Firestore-side pagination, we would need to modify the service methods to use cursors, but that was deemed higher risk for financial data. Instead, we paginate the UI after fetching the full dataset (which is required for calculations). This reduces React state size and rendering cost but does not reduce Firestore reads. To reduce Firestore reads, we would need to implement Firestore cursor pagination with separate UI-only queries, which is recommended for future stages.
- UI behavior: Shows first 50 ledgers/payments; 'Load More' button appends next 50; loading state and hasMore flags.
